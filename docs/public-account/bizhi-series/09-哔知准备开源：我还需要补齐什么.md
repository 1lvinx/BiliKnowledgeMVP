# 哔知准备开源：我还需要补齐什么

**文 / 逸峰AI**

哔知现在已经能支撑我自己的日常使用：从 B 站收藏夹选择视频，获取字幕或本地转写，生成洞察和笔记，再把 GitHub 项目提取到开源候选里。对个人工作流来说，它已经有价值；但如果要开源，问题就不只是代码能不能跑，而是别人能不能安全地安装、理解、使用和反馈。

开源前第一件事是清理个人数据。哔知处理的是收藏夹、字幕、笔记、Cookie、API Key、模型配置和本地知识库，里面有大量不应该出现在公开仓库里的内容。代码可以开源，真实数据不能开源；示例数据要能演示功能，但不能暴露个人习惯、账号信息和密钥。这是底线。

第二件事是把 README 写清楚。用户打开项目，应该马上知道哔知是什么、适合谁、解决什么问题、当前处于什么阶段、怎么安装、依赖哪些工具、一天建议处理多少视频，以及哪些场景不适合使用。尤其要明确它不是“自动总结所有收藏”的工具，而是一个半自动视频知识工作台，推荐每天精选少量高价值视频处理。

第三件事是补 Doctor。哔知依赖 Python、ffmpeg、yt-dlp、ASR 模型、AI API 和 B 站登录态，任何一个出错都会让用户卡住。Doctor 至少要能检查系统依赖、虚拟环境、模型缓存、Cookie 状态、API 配置和知识库目录，并尽量给出修复建议。否则开源后 Issue 区很可能被“为什么不能转写”“为什么抓不到字幕”淹没。

第四件事是写清楚风险边界。B 站接口、Cookie、字幕抓取、AI 成本和版权使用都需要明确说明。哔知只用于个人知识整理，不建议批量抓取，不提供绕过平台限制的能力，也不鼓励公开分发他人内容。AI 调用还要显示 token 和费用提示，避免用户因为误用产生高额成本。

第五件事是模块解耦。B 站解析、字幕获取、本地 ASR、AI 生成、笔记保存、开源项目提取应该尽量拆开，这样某一部分失效时不会拖垮整个项目，也方便社区以后替换实现。开源不是把所有东西堆出来，而是让别人能看懂边界，知道从哪里参与。

所以哔知开源前最重要的不是再加功能，而是把安全、文档、诊断、示例和边界补齐。只有这样，它才可能从“我自己能用”变成“别人也能稳定试用”。
