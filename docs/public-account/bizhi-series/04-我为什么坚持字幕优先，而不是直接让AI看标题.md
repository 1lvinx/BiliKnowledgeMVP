# 我为什么坚持字幕优先，而不是直接让 AI 看标题

**文 / 逸峰AI**

做哔知的过程中，我改过很多东西，界面、笔记模板、处理流程、开源候选链路都反复推倒过，但有一个原则越来越明确：生成洞察和笔记之前，应该尽量先拿到字幕，视频没有原生字幕就做本地转写，而不是把标题丢给 AI，让它凭经验写一段看起来合理的总结。

标题当然重要，它决定用户是否愿意点开视频，但标题不是内容本身。尤其在 B 站，很多标题天然带传播属性，比如“一个工具解决所有问题”“20 秒看懂”“彻底告别某某痛点”。这些标题可以帮助传播，却很容易误导 AI。模型只看标题时，往往会顺着标题脑补出一段正确但无用的话：这个视频介绍了一个提高效率的工具，适合某某场景。听起来没错，可它没有告诉你项目叫什么、怎么用、限制在哪里、视频里有没有实际演示，也没有留下任何以后能复用的线索。

字幕的价值在于提供证据。它把视频里的真实口播、操作步骤、工具名、命令、项目名、作者判断和限制说明转成文本，让 AI 有东西可依据，而不是只根据标题和常识凑答案。哪怕字幕有瑕疵，它也比标题更接近视频本身；如果字幕质量很差，至少可以提醒用户这条笔记需要人工复核，而不是悄悄生成一篇很漂亮但没有根据的文章。

我后来把哔知的链路设计成“字幕优先”，也是为了让笔记更像知识资产，而不是内容摘要。真正有价值的笔记应该回答几个问题：视频到底讲了什么？里面提到哪些工具、项目或方法？哪些信息可以复用？哪些结论来自字幕，哪些只是推断？如果视频里提到 GitHub 仓库，能否把仓库地址、Star、更新时间和用途一起沉淀下来？这些东西都离不开字幕。

当然，字幕优先并不等于迷信字幕。B 站原生字幕可能缺失，本地 ASR 也可能识别错误，所以哔知需要做校验、低置信提示和人工抽查入口。我的目标不是让 AI 代替判断，而是让它先把可用材料整理出来，再由用户决定哪些值得留下。标题可以作为入口，字幕才是证据；没有证据的总结，越流畅越危险。

这也是我不愿意把哔知做成“一键总结所有收藏”的原因。收藏夹里有太多只是当时觉得有用的内容，真正值得进入知识库的，应该经过一次选择、一次转写、一次提炼和一次确认。AI 可以帮忙干杂活，但知识沉淀这件事，最后还是要回到人自己的判断。
