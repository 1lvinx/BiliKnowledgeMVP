# 哔知是如何把 B 站视频变成知识库的

**文 / 逸峰AI**

哔知的核心思路很简单：不要把 B 站收藏夹当成终点，而是把它当成知识加工的入口。一条视频只有被转成字幕、提炼出关键内容、生成可检索的笔记，并且和项目、标签、想法产生关系，才真正进入了个人知识库。

目前我给它设计的主链路是：收藏夹导入，选择视频，抓取字幕或本地转写，生成视频洞察，生成 Markdown 笔记，再把笔记沉淀到本地知识库。这个流程不是为了追求全自动，而是为了让用户清楚知道每一步发生了什么。字幕是证据，洞察是提炼，笔记是沉淀，开源候选和想法则是后续复用的入口。

导入收藏夹后，哔知会把视频整理成本地清单，保留标题、UP 主、时长、收藏时间、BV 号和所属收藏夹。用户从里面挑选真正值得处理的视频，而不是让系统后台批量跑完所有内容。这样做看起来慢一些，但能避免信息囤积，也能控制 AI 成本和本地资源消耗。

字幕是整个系统的关键。如果视频有原生字幕，就优先抓取；如果没有，就用本地 ASR 转写。拿到字幕后，AI 才开始生成洞察，提取内容概述、核心观点、可复用价值、适用场景、限制风险和关键词。最后，系统会把这些内容整理成一份偏骨架化的 Markdown 笔记，方便后续搜索、编辑、导出和归档。

如果视频里提到 GitHub 项目，哔知会尝试识别仓库地址或项目名，并把它加入开源候选。这个设计对 AI 和开发者尤其有用，因为很多视频真正有价值的不是讲述本身，而是里面提到的工具、项目和方法能否落地到自己的工作流里。

所以哔知不是一个单纯的“视频总结器”，而是一个半自动视频知识工作台。它帮助用户把少量真正值得留下的视频，变成有来源、有证据、有结构、可复用的知识材料。
