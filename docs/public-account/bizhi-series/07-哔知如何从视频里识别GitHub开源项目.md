# 哔知如何从视频里识别 GitHub 开源项目

**文 / 逸峰AI**

在我自己的 B 站收藏夹里，有相当一部分视频和开源项目有关。很多 UP 主会介绍一个新工具、一个 GitHub 仓库、一个 AI Agent 框架，或者某个能解决实际问题的小项目。问题是，看视频时觉得有用，过几天就只记得“好像有个项目不错”，项目名、地址、使用场景和限制全都模糊了。

所以我给哔知加了“开源候选”这个功能。它不是单独做一个 GitHub 收藏夹，而是在生成笔记的过程中，顺手从字幕和洞察里识别可能出现的仓库、项目名和工具名，再尽量补全 GitHub 地址、Star、语言、更新时间、项目描述和来源笔记。这样视频里的资源不会只停留在口播里，而是能进入一个待筛选的候选池。

这个功能看起来简单，实际很容易做错。如果只靠标题，很容易误判；如果只让 AI 猜仓库名，也会出现不存在的项目。因此哔知更倾向于先从字幕里找明确线索，比如 GitHub URL、owner/repo 形式的名称、项目官网或反复出现的工具名，再去验证是否真的存在。匹配到仓库后，还要保留来源视频和来源笔记，避免以后不知道这个项目是从哪里来的。

我希望这个流程保持“被动提取 + 人工确认”。也就是说，视频生成笔记时如果识别到项目，就先放进“开源候选”，状态是待人工确认；用户看完后觉得确实有价值，再把它纳入自己的高价值资源库。这样既不会让系统擅自替用户收藏一堆项目，也能避免错过视频里一闪而过的好工具。

这个功能对 AI 和编程用户尤其有用。比如一个视频讲 Claude Code、Playwright、RAG、Agent 框架或本地模型工具，真正有价值的往往不是视频本身，而是它提到的项目能否复用到自己的工作流里。哔知需要做的，是把“视频里提了一嘴”变成“我以后能找到、能评估、能继续跟进”。

未来我还想继续完善这条链路：增加更精准的 GitHub 搜索、记录匹配置信度、展示仓库活跃度，并把项目和相关笔记、想法、标签串起来。最终它应该像一个个人开源情报夹，帮助我从视频内容里发现可落地的工具，而不是只留下一篇泛泛总结。
