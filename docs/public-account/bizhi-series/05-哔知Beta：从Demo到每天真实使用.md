# 哔知 Beta：从 Demo 到每天真实使用

**文 / 逸峰AI**

哔知最开始只是一个 Demo：能从 B 站收藏夹里读到视频，能生成一点笔记，看起来像是一个“AI 视频总结工具”。但真正开始每天使用后，我很快发现，Demo 能跑和产品能用是两回事。前者只需要证明链路存在，后者要面对真实收藏夹、真实字幕、真实依赖、真实失败和真实耐心。

我自己的收藏夹里有几千条视频，内容跨度很大，有 AI、编程、开源项目，也有一些已经失效或者标题很夸张的视频。刚开始我也想过批量处理，后来发现这条路很危险：后台跑得越多，电脑越卡，AI 成本越不可控，生成出来的笔记也不一定值得看。于是我把使用方式收窄成每天精选几条，优先处理 15 秒到 30 分钟的视频，一条一条完成字幕、洞察和笔记，而不是把收藏夹当成爬虫任务。

Beta 阶段最大的变化，是哔知从“能生成内容”变成了“能支撑日常工作流”。现在我会先在收藏夹里挑一条视频，如果有原生字幕就抓字幕，没有就本地转写；字幕可用后生成洞察，再根据洞察生成一份精炼笔记。如果视频里提到 GitHub 项目，系统会尝试识别仓库并加入开源候选，方便后面继续研究。整个流程并不追求全自动，因为我希望自己始终参与选择和判断。

这个阶段也暴露了不少问题。比如字幕缺失、ASR 低置信、模型依赖冲突、Cookie 过期、笔记路径不一致、界面信息太拥挤、状态提示不清楚。很多问题只有真实使用才会出现，单靠测试数据根本发现不了。尤其是本地转写链路，它涉及 Python、ffmpeg、yt-dlp、FunASR、模型缓存和网络环境，只要其中一环不稳定，用户就会觉得软件坏了，所以我开始补 Doctor 诊断、错误提示和更清晰的处理中心。

目前哔知还不是正式版，但已经进入我自己的日常使用：每天处理少量高价值视频，把值得留下的信息变成 Markdown 笔记，再继续整理到知识库里。它还不完美，可它已经解决了一个真实问题：收藏夹不再只是堆积内容，而是开始变成可以复用的知识来源。

对我来说，Beta 的意义不是急着发布，而是验证这件事能不能长期跑下去。一个工具如果只在演示时好看，却不能连续一周进入真实工作流，就不值得继续包装。哔知现在要做的不是增加更多功能，而是把少数关键链路打磨到稳定、可解释、可修复。
